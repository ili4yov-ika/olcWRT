# Правила разработки olcWRT

## Что это

olcWRT — клиент olcRTC для OpenWrt. Go-демон и CLI (`feed/olcwrt`), веб-интерфейс
LuCI (`feed/luci-app-olcwrt`) и упаковка в пакеты OpenWrt (`feed/`, `tools/pkgbuild`).

Демон запускает `olcrtc` дочерним процессом, заворачивает TCP трафик LAN в его
SOCKS5, резолвит DNS через туннель и управляет серверами, подписками и списками
из UCI.

## Структура репозитория

```
olcwrt/
├── feed/
│   ├── olcwrt/
│   │   ├── src/            # демон и CLI (Go, только стандартная библиотека)
│   │   └── files/          # init-скрипт, конфиг по умолчанию, списки
│   ├── olcrtc/             # пакет olcrtc (Makefile, исходники качаются с GitHub)
│   └── luci-app-olcwrt/    # LuCI: JS-вьюхи, po-переводы, rpcd, ACL, меню
├── tools/
│   ├── pkgbuild/           # сборка .ipk/.apk без OpenWrt SDK (+ po → lmo)
│   └── vm/                 # тестовый стенд: OpenWrt x86-64 в QEMU
├── SOURCES/                # референсные исходники olcrtc/olcbox (не коммитятся)
├── dist/                   # артефакты сборки (не коммитятся)
├── MARKDOWN/               # внутренняя документация для разработчиков
└── .github/workflows/      # CI
```

## Стек и ограничения

- `feed/olcwrt/src` — Go и **только стандартная библиотека**. Новые внешние
  зависимости не добавлять.
- LuCI — клиентский JavaScript без сборки; переводы через `po` → `lmo`.
- Целевые версии OpenWrt: 23.05 / 24.10 (opkg, `.ipk`) и 25.12 (apk, `.apk`).
- Интеграция с системой: `firewall4` (nftables) и `dnsmasq` через `conf-dir`.
- `olcrtc` — отдельный пакет и требует Go 1.26; сам `olcwrt` от него не зависит
  на этапе сборки.

## Правила кода

- Код, идентификаторы и комментарии — на английском. Пользовательские тексты
  (README, справка CLI, строки LuCI) — на русском.
- Каждый файл пакета начинается с краткого комментария о его назначении.
- Держать изменения минимальными: не добавлять абстракции «на будущее».
- Пути (`/var/run/olcwrt`, `/etc/olcwrt`, `/usr/bin/olcrtc`) не дублировать по
  коду — брать из переменных в `src/main.go`; они переопределяются через
  `OLCWRT_RUNDIR`, `OLCWRT_DATADIR`, `OLCWRT_LOG`, `OLCWRT_OLCRTC`, `OLCWRT_UCI`
  (нужно для тестов и запуска вне OpenWrt).
- Файлы состояния писать атомарно (`writeFileAtomic`, `writeJSON`). Права — не
  шире `0644`, для ключей и идентификаторов — `0600`.
- UCI читать и менять только через CLI (`uci -X show`, `uci batch`), используя
  `src/uci.go`. Напрямую в `/etc/config` не писать.
- Внешние команды (`nft`, `uci`, `ubus`, `dnsmasq`) запускать с таймаутом
  (`runWithTimeout`) и обрабатывать ошибку.
- Сетевые операции — с `context` и дедлайном. Долгие операции не выполнять под
  общим мьютексом демона: event-loop не должен блокироваться.
- После изменения поведения обновлять README и, при необходимости, этот файл.

## Что olcWRT меняет в системе

- Таблица nftables `inet olcwrt`.
- Файлы `olcwrt.conf` и `.olcwrt.servers` в `conf-dir` dnsmasq.
- Ничего из этого не должно оставаться после остановки. При падении демона
  остатки убирает `olcwrt cleanup` (его вызывает init-скрипт).

Добавляя новое вмешательство в систему, обязательно предусматривайте его
удаление в `teardown`/`cleanup`.

## Тесты

Тесты лежат рядом с кодом (`*_test.go`).

```sh
cd feed/olcwrt/src
go vet ./...
go test -race ./...
```

- Новое поведение сопровождать тестом.
- Системные вызовы изолировать: подменять `PATH` фейковыми `nft`/`uci`/`ubus`
  или задавать `OLCWRT_*` и работать во временном каталоге.
- Для сети использовать `httptest` и фейковый SOCKS5, а не реальные сервисы.
- Тесты и `go vet` должны проходить до коммита; CI проверяет то же самое.

## Сборка

```sh
cd tools/pkgbuild
go build -o pkgbuild .
./pkgbuild -arch mipsel_24kc,aarch64_cortex-a53   # .ipk
./pkgbuild -arch all -apk /path/to/apk.static      # .ipk и .apk
```

- Версии пакетов берутся из `PKG_VERSION`/`PKG_RELEASE` в Makefile — не
  дублировать их в коде.
- Для `.apk` нужен `apk-tools` 3; на Windows он запускается через `wsl:`.
- Не коммитить `dist/`, `.bin/`, `.gotmp/`, `SOURCES/`.

Сборка через OpenWrt SDK/buildroot описана в README (`feed/` — обычный фид).

## Переводы

После изменения строк интерфейса:

```sh
cd tools/pkgbuild
./pkgbuild pot          # обновит шаблон и допишет новые строки в po/ru/olcwrt.po
```

Переводы — `feed/luci-app-olcwrt/po/<lang>/olcwrt.po`.

## Документация

- `README.md` — обзор, установка, настройка, CLI, сборка. Основной источник для
  пользователей.
- `MARKDOWN/` — внутренние заметки для разработчиков (этот файл, архитектура).
- Справка CLI — `usageText` в `src/main.go`; синхронизировать с README при
  добавлении команд.
